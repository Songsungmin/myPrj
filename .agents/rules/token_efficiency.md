# 프로젝트 토큰 효율화 상세 규칙 (Project Token Efficiency Rules)

본 규칙은 **Model Decision**(모델 판단에 의한 동적 참조 방식)으로 동작하며, 작업 수행 중 토큰 최적화 및 효율적인 파일 처리가 요구될 때 자동으로 호출됩니다.

## 1. 프로젝트 파일 접근 및 탐색 제한
- `node_modules/`, `.next/`, `backend/node_modules/`, `dist/`, `build/` 등 의존성 및 빌드 결과 폴더에 대한 재귀적 탐색을 엄격히 금지합니다.
- 특정 파일 점검 시에는 전체 디렉토리 탐색 대신 필요한 파일의 절대 경로를 직접 지정하여 읽습니다.
- 파일의 특정 부분만 확인할 때는 `StartLine`과 `EndLine`을 지정하여 필요한 라인 범위만 조회합니다.

## 2. 터미널 명령 최적화 (PowerShell 환경)
- 패키지 설치(`npm install`) 시 불필요한 상세 로그 출력을 줄입니다.
- 프로세스 점검 및 파일 목록 확인 시 `Select-Object -First 10` 또는 `-Filter` 옵션을 적극 활용합니다.
- 동일한 상태 정보나 디렉토리 구성을 확인하기 위해 동일하거나 유사한 명령을 반복 실행하지 않습니다.

## 3. 코드 작업 및 수정 범위 제약
- 사용자가 요구한 컴포넌트(`page.tsx`), 서버 코드(`server.js`), 설정 파일에 한정하여 수정합니다.
- 관련 없는 코드의 서식 재지정(Formatting)이나 사전 요청되지 않은 리팩터링은 수행하지 않습니다.
- 독립적으로 수행 가능한 파일 생성 및 편집 작업은 불필요한 중간 대기 없이 연계 처리합니다.

## 4. 검증 및 테스트 원칙
- 작업 완료 여부 확인을 위한 최소 단위의 기능 테스트(예: 헬스체크 엔드포인트 호출 또는 특정 컴포넌트 빌드 확인)만 수행합니다.
- 기능이 정상 작동함을 확인한 후에는 불필요하게 추가 검증이나 동일한 상태 확인을 반복하지 않습니다.
- 코드의 정확성과 보안성 검증(예: CORS 설정, 입력값 처리 등)은 토큰 절약을 핑계로 생략하지 않고 철저히 수행합니다.
